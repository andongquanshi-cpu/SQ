# PWA 照片共享验证版 v0.1

状态：已实现，代码在 [apps/photo-share-demo/](../apps/photo-share-demo/)。两部真机已在局域网（电脑运行服务）完成测试，结果正常。下一步部署到 HTTPS 云端地址，完成"开发者电脑关闭后复验"和添加到桌面的验收。云服务供应商尚未选定。

## 已确认

- 两人使用：小米 15 与 iPhone，各自账号，同一个私人旅行本。
- 运行方式：PWA 手机网页 App，浏览器打开并验证添加到桌面。
- 连接真实云端，照片和已保存的信息不依赖开发者电脑保持开机。
- 双方都能上传、查看照片，并补充文字备注、地点或标签。
- 首个验证版本先完成照片共享；行程、记账、AA 继续保留在整体 v1 计划内。
- 拼贴视觉随后细化，首轮不做图片圈画或手写编辑。

## 第一轮功能

1. 独立登录：识别当前用户，进入双方共享的旅行本。
2. 共享照片：双方都可从各自手机选择照片；上传成功后进入共同相册。
3. 照片详情：查看图片、上传者及双方补充的信息。
4. 文字备注：向同一照片添加文字，保留作者与时间。
5. 地点与标签：添加手动地点名称或文字标签；不依赖地图定位服务。
6. 同步与保留：云端确认保存后，另一端可以读到；重新打开后仍可读取已同步内容。
7. 基本失败恢复：上传失败明确提示并允许重试，重复提交避免重复照片或备注。

照片可以独立上传到旅行本，不要求先创建手账文章。

## 协作规则建议

以下是可修改的实施建议，不视为用户已逐项确认：

- 文字备注按作者分条追加，两人同时补充时各自保留；各自修改、删除自己的备注。
- 地点为照片的共享文字信息；修改时带版本，旧版本写入提示重新读取，避免静默覆盖。
- 标签共同补充，同一照片的相同标签去重；新增、移除采用独立操作。
- 照片删除先建议由上传者操作，并采用可恢复标记；恢复期限及删除后的备注处理另行定稿。
- 未完成上传的照片不显示为已共享；只有服务端确认后才显示“已同步”。
- 首轮以联网、应用打开时的使用为准，不承诺锁屏后持续上传或完整离线编辑。

## 页面职责

- 登录／加入旅行本：完成账号识别及成员加入。验证时可使用受控测试邀请，不以界面美观作为通过条件。
- 共同相册：列出已上传照片，显示上传中、失败及完成状态。
- 照片详情：显示照片、上传者、备注、地点和标签，提供补充入口。
- 上传入口：选择真实照片、预览、提交及重试，不使用示例照片冒充真实上传。

## 前后端职责

- 前端：移动端选图、必要格式处理、信息编辑、上传状态、读取云端更新与桌面入口配置。
- 账号与权限：校验当前用户属于这本旅行；非成员不能读取照片或标注。
- 文件存储：私有保存照片及兼容的浏览版本；具体供应商、转换方式和容量预算待落实。
- 数据库：保存旅行成员、照片元数据、文字备注、地点、标签、作者及版本。
- 同步：写入云端成功后通知另一端重新读取；回到前台或重新打开时主动刷新，不能只依赖一次实时通知。
- 本机缓存：仅作缓存、草稿或必要的待上传暂存；云端已确认内容才是共享依据。

## 两部真机的验收步骤

1. 两人使用各自手机和日常网络打开真实 HTTPS 测试地址，分别登录并进入同一本旅行；测试添加到桌面的入口。
2. 小米上传一张真实照片，iPhone 读到云端保存的同一照片，并能正常放大查看。
3. iPhone 为这张照片补充自己的文字备注、地点或标签，小米收到更新；原有备注仍保留作者与内容。
4. 交换上传方：iPhone 选取真实照片，包括 HEIC 来源样本，确认小米能正常显示且方向正确。
5. 两部手机关闭并重新打开，仍能从云端读到照片和双方已保存的信息；开发者电脑关闭后复验。
6. 上传过程中断网，界面不误报成功；恢复网络后按提示重试，同一提交不生成重复记录。
7. 双方同时新增备注均保留；共享地点发生旧版本写入时给出可恢复提示，不静默覆盖。
8. 非成员读取被拒绝；退出或切换账号后，不继续显示上一账号的私有缓存。

本文件定义“怎样算验证通过”，不代表真实账号、云端地址、供应商或费用已经落实。整体产品规划见 [开发蓝图 v0.2](travel-journal-blueprint-v0.2.md)。
